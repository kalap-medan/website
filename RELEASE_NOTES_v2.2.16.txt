KALAP Management System v2.2.16

Perbaikan fokus pada sinkronisasi saldo stok harian dan penolakan Firestore:

1. Memindahkan aturan otorisasi sinkronisasi saldo harian menu Mitra ke cabang pertama pada `menus/{menuId}` update. Cabang ini tetap mensyaratkan profil staf aktif (Superadmin/SPV), `partnerId` string non-kosong, saldo bilangan bulat non-negatif, tanggal bisnis valid/berbeda, `updatedAt == request.time`, dan hanya tiga field saldo/tanggal/waktu yang boleh berubah.
2. Mengurangi ukuran batch sinkronisasi saldo mitra dari 450 menjadi 8 dokumen per batch untuk menjaga batas document-access-call Firestore pada operasi batch.
3. Menambahkan rincian sub-tahap sinkronisasi: membaca status closing, membaca daftar menu, membaca catatan pergerakan stok, atau kelompok pembaruan saldo. Jika masih ada penolakan, pesan berikutnya akan menunjukkan operasi spesifik yang ditolak.
4. Perbaikan ini menyentuh jalur sinkronisasi bersama yang dipanggil saat input manual, edit/hapus batch stok, reset harian, dan pergantian tanggal.

Berkas yang diperbarui:
- `index.html`
- `firestore.rules`
- `service-worker.js`
- `README.md`
- `RELEASE_NOTES_v2.2.16.txt`

Pemasangan:
1. Publikasikan `firestore.rules` dari paket ini ke project Firebase yang benar, `kalap-63628`.
2. Ganti `index.html` dan `service-worker.js` di hosting dengan file dari paket ini.
3. Pertahankan `manifest.webmanifest`, `firestore.indexes.json`, folder `icons/`, dan konfigurasi hosting yang sudah ada.
4. Lakukan hard refresh (`Ctrl + Shift + R`) dan pastikan versi aplikasi tampil sebagai v2.2.16.

Batas verifikasi:
- Sintaks JavaScript, struktur kurung Firestore Rules, dan integritas ZIP diperiksa secara lokal.
- Lingkungan ini tidak memiliki akses kredensial untuk mempublikasikan Rules atau menjalankan operasi terhadap Firebase produksi. Karena itu status publikasi Firebase harus dikonfirmasi di Firebase Console setelah file Rules dari paket ini dipasang.
